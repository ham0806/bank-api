# 要件

## 対象範囲

- 口座作成、残高照会、取引履歴
- 入金、出金、口座間振込
- 冪等性
- 残高と仕訳の整合性
- PostgreSQL行ロックによる同時実行制御
- Transactional Outboxと模擬外部金融機関

認証・認可、手数料、限度額、複数通貨、為替、実際の金融機関接続は対象外です。

## 業務ルール

1. 金額は1以上の円単位整数である。
2. 送金元と送金先は異なる口座である。
3. 出金・振込予約は利用可能残高を超えてはならない。
4. 入出金、確定振込は残高と仕訳を同一トランザクションで更新する。
5. 一つの振込には送金元の負数仕訳と送金先の正数仕訳を作成する。
6. `balance_minor` は対象口座の仕訳合計と一致する。
7. 顧客口座の`reserved_minor`は確定残高以下である。`SYSTEM-CLEARING`口座は相反仕訳の清算差額を保持するため、負残高を許容し、顧客向けAPIからは操作できない。
8. 同じIdempotency-Keyと同じ内容の再送は、同じリソースを返す。
9. 同じIdempotency-Keyと異なる内容の再送は拒否する。

## 振込状態

```text
PENDING -> COMPLETED
PENDING -> FAILED
```

`PENDING` の間は送金元の金額を予約します。外部連携成功後に予約を確定仕訳へ変換し、失敗時は予約を解除します。
